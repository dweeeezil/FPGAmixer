# FPGAmixer

FPGA-based digital matrix mixer on the Digilent Genesys ZU-3EG (Zynq
UltraScale+ MPSoC), with analog (Pmod I2S2), USB and network audio (AVB) as
interchangeable "front doors" into one PCM core, controlled from the
StudioRunner macOS app over OSC, with every setting surviving a power cycle.

See `docs/archive/FPGA Network Audio Device.md` for the original goals,
`docs/FPGAmixer_Architecture_Roadmap.md` for the phased plan and where each
phase stands, and `docs/architecture_modules.md` for how the blocks are
allowed to connect.

## What it does today (October 2026)

```
 4 Pmod in ─┐                                                 ┌─ 4 Pmod out
 8 USB in  ─┼─ input   → input   → bus    → bus     → output ─┼─ 8 USB out
 8 AVB in  ─┘  levels    matrix    levels   matrix    levels   └─ 8 AVB out
               (20)      (20→20)   (20)     (20→20)   (20)
```

- **20 inputs, 20 buses, 20 outputs**, a level on every one of them, and two
  20 × 20 crosspoint matrices (input → bus, bus → output). All of it runs in
  the PL inside one audio frame on 11 DSP48E2s (Phase 12).
- **Front doors:** two Pmod I2S2 modules (JB, JC); the Mac sees the board as an
  8 × 8 USB audio device (UAC2 gadget on the Type-C port); and as an AVB device
  on Ethernet (gPTP on the PS GEM, AAF streams, AVDECC entity), 8 channels each
  way. `mclk` is steered onto gPTP time, so the network disciplines the core's
  own clock.
- **Control:** an OSC server on the board (TCP 8000 with length-prefixed
  framing, UDP 8001; Bonjour `_studiorunner._tcp`) implementing
  `docs/FPGA Mixer OSC Standard.md`: zones `inputChannel`, `inputMatrix`,
  `busChannel`, `busMatrix`, `outputChannel`, a config reply the app builds its
  UI from, error replies, ping. State is saved crash-safely and restored at
  boot.

Phase status, open items and what's next: the roadmap's table and §5. The
newest status doc is `docs/phase12_status_2026-10-04.md`.

## Building

**FPGA** (Vivado 2026.1 with the Digilent board files; board_part
`digilentinc.com:gzu_3eg:part0:1.0`, device `xczu3eg-sfvc784-1-e`):

```
vivado -mode batch -source scripts/create_project.tcl
vivado -mode batch -source scripts/build.tcl -tclargs <tag>
```

`create_project.tcl` builds the `current_phase` variant (`phase9`: PS, both
links, media clock; the core is the same in every variant). `build.tcl` writes
`build/<tag>_*.rpt` and `build/fpgamixer_<tag>.xsa` and fails on negative slack
or a methodology critical warning. Then `sdtgen -xsa build/fpgamixer_<tag>.xsa
-dir build/sdt`.

**Linux image** (EDF/Yocto on a build VM, `docs/setup_edf_hyperv_vm.md`): copy
the SDT to the VM, `scripts/sync_buildhost.sh`, then `gen-machine-conf` (only
when the hardware changed) and `bitbake edf-linux-disk-image xilinx-bootbin`.
The status docs record each image (`build/sd/<name>.wic.xz` and its MD5).

## Testing

```
.\scripts\xsim_regress.ps1                 # all 20 testbenches (Windows, XSim)
.\scripts\xsim_regress.ps1 core gain       # some, by name
make -f scripts/sim.mk all                 # the same in Icarus
cd tools; python -m unittest               # the board software
```

The RTL testbenches are bit-exact against reference models and check timing to
the cycle; new tests are mutation-tested. The register-window tests in
`tools/test_mixer_hw.py` need Linux (run them on the build VM, whose Python
matches the board's). On Windows, an XSim "child exe not found" is the tool
being blocked (Defender), not a test failure: rerun.

## Hardware

- Genesys ZU-3EG (Zynq UltraScale+ MPSoC, `xczu3eg-sfvc784-1-e`)
- 2× Digilent Pmod I2S2 (CS5343 ADC + CS4344 DAC) on the digital Pmods **JB**
  and **JC** (JA is the analog XADC Pmod)
- Gigabit Ethernet (TI DP83867 → RGMII → PS GEM0) with 1588 hardware
  timestamping: gPTP and AVB
- USB Type-C (PS USB0) in device mode: the Mac's 8 × 8 soundcard
- Bench: a Mac on a direct cable (OWC Thunderbolt 4 10G adapter); the board
  is `amd-edf.local` (IPv4 link-local + mDNS)
